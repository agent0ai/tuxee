# Purpose

Authenticated HTTP API, application sessions, per-user settings, and WebSocket terminal views.

# Ownership

Own HTTP routing and session revocation. Delegate filesystem syscalls to files, account checks to identity, process discovery/signals to processes, and all terminal lifetime/control to terminal.

Terminal sessions own GUI lifetime. After the existing terminal UID check, `GET /api/terminals/{id}/display` returns the running display's temporary VNC password; it never starts a display. Its `/ws` suffix bridges the private Unix VNC socket through authenticated, same-origin binary WebSocket frames. `/api/terminals/{id}/display/window` accepts POST to activate and DELETE to request a normal window close; both require CSRF and a window ID from that display. Accept no caller-provided destination. Logout revokes transports while retaining the terminal and applications.

Ping VNC WebSockets every 20 seconds with an eight-second pong deadline, matching terminal liveness. On failure, cancel both bridge directions and release only that viewer; preserve the terminal, X display and applications. Clipboard transport remains independent, with its existing 30-second ping/five-second deadline.

Terminal `/display/clipboard/events` streams XFixes version/local notifications through an authenticated same-origin WebSocket; require Origin and revoke on logout. `/display/clipboard?version=N` reads only that current clipboard version. CSRF-protected POST `/display/clipboard` accepts one bounded text, base64 PNG or absolute Linux file list; POST `/display/drop` accepts files plus display coordinates and a window from that terminal. Both reuse terminal UID admission. Limit clipboard/drop payload operations to two server-wide before reading bodies, bound JSON to the owning data limits, and impose 30-second HTTP deadlines. X11 reads/drops also have ten-second cancellation. No caller-supplied X endpoint, UID, command or privileged filesystem access.

`GET /api/audio` subscribes only to the authenticated Linux UID's shared audio manager. Require the shared origin/session admission plus explicit WebSocket Origin; accept no source, UID or client audio/input messages. Send 960-frame packets of 48 kHz stereo signed 16-bit little-endian PCM with an 8-byte little-endian sample position; omit digital silence. Bound writes to 250 ms and ping during silence. Disconnect/logout releases that browser subscription; the last listener stops shared capture without terminating applications. `/api/me` reports optional audio-runtime availability. There is no per-terminal audio route.

# Local Contracts

The index embeds one safely JSON-escaped English-fallback/selected-language dictionary in a non-executable JSON element, with the selected document language/direction, `private, no-store` and `Vary: Accept-Encoding, Cookie`; preserve the executable script CSP hash. Read the browser-managed `tuxee_language_<instance-id>` preference only for anonymous pages. Login accepts the displayed language and freezes its merged bundle for that session; terminal creation takes its language from this authenticated snapshot, never a caller-supplied terminal language or current preference cookie; authenticated index, `/api/me` and `/api/language` use the same snapshot, regardless of cookie/query changes. `/api/connection` includes session language so other tabs reload when login replacement changes it. Anonymous `/api/language` refreshes catalogs for explicit selection. API failures retain diagnostic `error` and add structured `text: {key, vars}`; streaming/download status must retain the same metadata.

The files API admits `trash`, `trash-list`, `trash-restore`, `trash-delete` and `trash-empty` through the existing authenticated, CSRF-protected worker/file-slot path. The worker owns discovery and metadata validation; accept no client trash-root override. File panels may persist the exact virtual path `trash:///`; terminal panels still require filesystem paths.

The CLI supplies its persistent instance ID to `New`; use `tuxee_session_<instance-id>` consistently for login, lookup, re-login revocation and logout. Only that exact cookie authenticates requests. Ignore other instances' and legacy `tuxee_session` cookies without deleting them. Keep the existing host-only Path=/, HttpOnly, Strict and proxy-aware Secure attributes; the ID names a cookie, never authenticates a user. Cookies remain hostname-scoped in browsers, so names avoid collisions but do not provide port-level secrecy.

Cookies contain random revocable tokens; login passwords never leave the isolated authentication path. Archive passwords are transient filesystem-worker input. Mutations require same-origin admission and a session CSRF token. Apply Go `http.CrossOriginProtection` unsafe-method checks to every API method, including WebSocket GETs: browser Fetch Metadata or Origin/Host comparison must tolerate TLS termination without deployment configuration. Keep explicit Origin required for both WebSocket transports. An existing optional origin override supplies the fallback target host; no forwarded host header may authorize requests. Direct TLS, an HTTPS browser Origin or `X-Forwarded-Proto: https` enables Secure cookies and HTTPS metadata links; headers cannot downgrade a TLS request. Logout cancels all requests/WebSockets associated with that login, but never closes retained PTYs. Every terminal operation verifies its Linux owner. User settings validate whole-layout bounds and overlap before an atomic user-owned save. Accept only 4×2 or 2×4 grids and at most eight panels per workspace on save. Loading validates legacy 8×2 geometry before converting: halve horizontal coordinates when valid, otherwise place one panel per cell; retain scaled custom snapshots only when valid. Split panels beyond eight into another workspace, preserving metadata, terminal IDs and the active panel. Never migrate malformed input or terminate sessions. Settings may hold up to 24 workspaces to preserve all panels from twelve legacy sixteen-panel workspaces; ordinary UI creation remains capped at twelve. File transfers stream under the user's credentials.

Close marks the service unavailable before revoking logins. While shutting down, return no-store JSON 503 responses, including health, assets and login; never report revoked shutdown sessions as expired credentials or admit a login after Close. Healthy `/health` is also uncached. `GET /api/connection` is the browser readiness contract: return no-store JSON 200 with `authenticated: true/false` based on the same cookie/session admission as other APIs. Authenticated responses also include the current Linux `uid` and session `csrf` token; anonymous responses omit both. Missing, invalid and expired cookies report false only while the service is available; shutdown always reports 503, never a ready anonymous session. Keep `/health` for container liveness.

`POST /api/restart` requires authentication and the shared origin/CSRF admission. Accept no client command or PID. Before changing runtime state, use the credential-dropped processes worker to check the signed-in user's kernel signal permission against its parent (Tuxee); share the process-signalling concurrency limit. Return a denial with the server executable's shell-safe restart command, prefixed with sudo for non-root users, without interrupting sessions. Do not hardcode UID 0 or elevate through sudo. Atomically mark the runtime unavailable before returning 202, then notify the CLI through the installed Restart callback. Reject duplicate requests during shutdown; return 503 without closing the runtime if restart is unavailable. The CLI owns cleanup and re-execution.

Terminal lifetime has no timeout setting. Optional `closedTerminalHistoryHours` is archive retention after explicit closure only: absent/null defaults to 168, integers 0–876000 are accepted, and zero is preserved. Ignore legacy `idleHours` when loading settings and accept/drop it on save, so existing clients and saved layouts remain usable. Never include it in returned or newly persisted settings.

Optional `serverName` is a per-user display label in the existing user-owned `~/.config/tuxee/settings.json`. Normalize surrounding whitespace on load and save; reject NUL and more than 64 UTF-16 code units, matching the browser input's maxlength. Empty names are omitted from persisted/returned JSON and use the hostname in the UI. Keep aliases authenticated; the public index and `/api/system` retain the real hostname. This setting never changes the Linux hostname.

Optional `serverColor` in the same per-user settings stores the top-bar color marker. Accept only `#RRGGBB` hex colors or empty/absent values for the theme default; omit empty values when saving/returning JSON. Keep validation shared between load and save and never accept arbitrary CSS.

Optional `terminalBackground` (dark) and `terminalBackgroundLight` use the same six-digit hex validation and omission rules; empty/absent means `#1b2230` and `#f8f9fc` respectively. Resolve colors from the saved UI theme, with fixed foreground `#e6edf3` for dark and `#1c2638` for light. Theme changes update retained sessions through the same settings-save path. After a successful atomic save, update that Linux user's retained terminals through the manager. Creation reads the saved preference before starting the shell. Serialize settings saves and terminal creation so concurrent creation cannot miss a saved color; failed saves never change terminal palettes.

Optional `terminalFontSize` in per-user settings accepts every integer from 6 through 128 on load/save, including values between browser presets. Absent/null values are omitted and use the frontend default of 13px. Optional `terminalFontFamily` is trimmed, bounded to 512 UTF-16 code units and omitted when empty; absent/null/blank uses the frontend system monospace stack. Reject control characters, CSS declaration/rule delimiters, backslashes, angle brackets and comment openers because xterm inserts the family into its renderer stylesheet; browser input also checks font-family syntax. These are browser rendering preferences; no font installation or shell changes. The existing terminal resize protocol carries resulting cell dimensions without restarting sessions.

Optional user/workspace `defaultDirectory` persists in the existing per-user settings. Load/save accepts empty, `~`, `~/…` or an absolute path, bounded to 4096 bytes without NUL; empty fields are omitted. The frontend owns workspace inheritance and clearing overrides equal to the global directory. A terminal API create without an explicit directory uses the saved user default, expanding `~` against the authenticated home; ordinary file/terminal workers retain Linux permission checks and report unavailable paths. Settings validation never accesses paths as the server account. Preserve directory preferences through legacy workspace splitting.

Optional `shellCommand` and `useTuxeePrompt` are per-user creation preferences: blank/absent command means `bash`, absent/null prompt means enabled, and explicit false must round-trip. Trim command whitespace; reject NUL/line breaks and more than 4096 bytes. Pass the saved settings to terminal creation under the existing settings lock. Never alter retained shells or execute/validate command text under server credentials.

Optional `shortcuts` uses the existing per-user `~/.config/tuxee/settings.json` and atomic credential-dropped save. It maps known action IDs to exactly two arrays of zero to three canonical physical-key strokes (Control, Alt, Shift, Meta in that order plus a supported KeyboardEvent code). Missing actions use frontend defaults; empty arrays explicitly disable slots. The known actions include `panel.close` for the focused-panel Close command. Reject unknown actions, null slots, malformed/unbounded strokes, unmodified first keys other than F1–F12, and duplicate/prefix-conflicting stored sequences on both load/save. Frontend validation also compares against defaults. Shortcut settings never execute commands or bypass action permissions.

Optional `editorLineWrap` is a per-user editor display preference. Absent/null means enabled; explicit false must round-trip through saved/returned settings. It changes no file contents or page limits.

Optional `uploadConcurrency` in per-user settings accepts only integers from 1 through 64 on load/save, preserving legacy values between the browser's power-of-two choices. Absent/null values are omitted from returned/saved JSON and use the browser's default of 4. This configures each browser upload batch; the server independently limits shared file operations to 64 and rejects excess operations with 429.

`POST /api/upload?path=…&unique=true` streams a size-declared file through the credential-dropped worker and returns its actual `path`. The worker owns collision naming; the HTTP layer must not pre-check or retry destinations. Omitted/false unique keeps explicit no-overwrite behavior for New file. Directory upload preparation uses the existing files API's mkdir with unique or parents flags.

`POST /api/download-archive` registers a sibling selection and returns a random session-bound token/name. `GET /api/download?archive=token` claims it once and streams the worker's ZIP immediately without Content-Length or a temporary archive. `GET /api/download-archive?token=token` reports compressed bytes sent, completion and errors; DELETE cancels/removes it. Require the same login for every operation and CSRF for registration/cancellation. Bound pending records to 128 and active workers through the shared file slots; expire unused/completed records after one minute and stop active streams after 30 minutes. Logout/disconnection/cancellation stops the worker. Failed ZIP streams must abort the HTTP response instead of reporting a successful partial archive.

Multiple selected items use the cleaned parent directory's basename plus `.zip`, or `sys-root.zip` for `/`. A single selected folder retains its own name plus `.zip`. Registration, progress UI and Content-Disposition share this server-owned name.

Optional workspace `layout` stores auto mode 1/2/3 and `custom` geometry keyed by panel ID. Validate both current and saved positions with the same bounds/overlap check; the custom snapshot must contain exactly the current panel IDs, without duplicates. It stores no paths or terminal identities. Absent layout means custom and remains compatible with older settings.

Panels have no display-name field. Loading older saved settings ignores file-browser aliases while preserving paths/layouts; newly returned and saved settings omit them. Terminal sessions own their names. The only panel kinds are `files` and `terminal`; there is no separate GUI kind or GUI launch API.

File panels may persist an optional `pinned` boolean; absent means unpinned. Authenticated `GET /api/terminals/{id}/cwd` returns the current directory only for an owned, live terminal, using the terminal's credential-dropped lookup. Never accept a client PID.

ServeHTTPS wraps the existing Go TLS listener to return an empty 308 redirect for plaintext HTTP on that same port. Preserve the request host, explicit port, escaped path and query; do not trust forwarded headers. Never pass plaintext requests received on the TLS socket to application handlers. Use the existing TLS handshake deadlines and bounded header parsing; malformed requests return 400. Keep the wrapper small: no separate protocol dispatcher or listener lifecycle. The CLI owns which protocol sockets exist. The separate HTTP listener and legacy explicit --http serve the application directly, even when HTTPS is enabled. Use the shared proxy-aware cookie security and WebSocket admission without weakening authentication or CSRF.

The bundled index inline script requires the build-generated SHA-256 CSP hash. Substitute the existing origin(r), running environment's hostname and executable version into the index in one pass, HTML-escaping every value. Use the shared public-scheme inference and optional origin override; never take the hostname from forwarded headers. Hostname/version metadata and the `Tuxee hostname` title are public so login needs no additional API request; account details remain authenticated. Negotiate gzip after substitution; use one gzip stream so browsers receive the complete page. Keep the index and unversioned static resources `no-cache` so refreshes revalidate across upgrades. Only existing generated files under `/assets/` use `public, max-age=31536000, immutable`; their build-generated filenames contain content hashes. Never give directories, missing assets or traversal paths immutable caching. Open Graph/social URLs are absolute; public favicon/preview files contain only static branding, never authenticated data.

Terminal recovery sends a JSON snapshot and waits for its render acknowledgement before live output or input. Negotiate stateless WebSocket deflate. Live output uses binary frames with an eight-byte big-endian sequence followed by PTY bytes; metadata remains JSON with the same sequence. Bound outstanding live output to 64 events/256 KiB (one larger metadata event may use the attachment's 1 MiB budget alone) and accept only advancing acknowledgements of sent sequences. Allow two minutes for recovery and ten seconds for live rendering. Accept an input pipeline of at most 64 frames totaling 64 KiB, including the active write. One worker writes frames strictly in arrival order and acknowledges each only after PTY consumption; check attachment ownership for every write. Blocked stdin must not block render acknowledgements or heartbeats, and cancellation drops queued frames without replay. Bound control JSON to 4 KiB; reject malformed, unknown, premature or out-of-window input by detaching that view. A successful resize receives a separate resize-ack. Terminal identity is separate from cookies and views.

Authenticated `GET /api/system` supplies the About modal with the executable's version, OS release, kernel, architecture, hostname and the current session's username, UID, home and shell. Read system metadata within the running environment, including containers; never substitute the server process account for the signed-in user. The CLI passes the same version used by `tuxee version`.

Authenticated `GET /api/tls` describes the request's backend transport. HTTP returns only `source: http`, even when a TLS manager exists. Return managed certificate status only for TLS requests without `Forwarded`, `Via` or `X-Forwarded-*` headers; select the identity from TLS SNI, using the manager's default when SNI is absent, never the HTTP Host. Other TLS requests return only `source: https`. Omit backend certificate expiry/errors/CA claims for identifiable proxies. The frontend owns the browser-facing HTTP/HTTPS label. Re-encrypting proxies that send no proxy indicators cannot be distinguished from direct TLS.

Authenticated `GET /api/metrics` returns the shared monitor snapshot with no-store caching headers. It accepts no user paths or interface queries. Optional per-user `monitoring` settings select CPU/RAM/swap, up to eight absolute mount paths and eight network selections (Linux interface names or the reserved `/all` aggregate), and a 2/5/10-second refresh interval. The optional boolean `hidden` hides persistent gauges; absent/false keeps them shown and does not restrict on-demand metrics access. Missing preferences retain frontend defaults; validate names, duplicates, counts and interval before the existing user-owned atomic save.

Authenticated `GET /api/processes?sort=ram|cpu&allowCore=true|false` passes the validated sort to the credential-dropped worker for visible command-line previews, returning at most 1,000 process/group/zombie rows and a random session-bound snapshot ID. Keep one immutable full snapshot per login, replacing it on refresh/sort; other views using the previous ID must refresh. Release it on matching CSRF-protected DELETE, logout or after 30 minutes. POST accepts only that snapshot ID, displayed selection IDs and signal 15/9; resolve grouped descendants from the saved snapshot and delegate identity/permission checks and signals to processes. Process RAM and file-backed PSS fields are nullable; pass through the owning sampler's per-process, aggregate and target estimate flags without recalculating memory. Core-process permission defaults to false, is fixed in the snapshot and returned as `allowCore`, and must match the explicit POST value before the helper may bypass ancestor protection. Toggling it requires a fresh snapshot. No arbitrary client PID/command execution and no discovery of new kill targets. Bound reads and kills independently to two concurrent helpers each; helpers have a 30-second deadline. Responses remain no-store, mutations require the existing origin/CSRF admission, and cancellation/logout stops workers.

Authenticated `GET /api/update` reads the shared cached update status and a command for this server executable using `update.Command`: short `tuxee` when PATH resolves to the same installation, otherwise the shell-quoted absolute path, with sudo for non-root users. CSRF-protected POST requests a rate-limited check through internal/update. Neither endpoint installs or restarts. The CLI starts the checker with the server lifecycle; failures retain known update availability.

`POST /api/file-size` uses normal session/origin/CSRF admission and streams no-store NDJSON from the credential-dropped file worker. Limit scans to two globally, each with a five-minute deadline and five-second write deadlines. Disconnect, aborted requests and logout cancel/reap the worker; the file client escalates unresponsive helpers after three seconds. Accept only a bounded list of paths, with validation owned by the worker.

Owned `GET /api/terminals/{id}/input-history` returns the terminal’s drawer string array; CSRF-protected POST appends one `text` field and returns the updated list. Never accept a client path, UID or installation ID. Delegate bounds, serialization and files to the terminal manager. Successful login registers the username/UID for archive cleanup and reconciles that user’s records; logout only detaches. `GET /api/terminals` merges live sessions and owned installation archives. ID lookup returns live metadata when available, otherwise archived metadata (`exited`, optional lifecycle timestamps and computed `expiresAt`, no live PID). Owned `GET /api/terminals/{id}/archive` returns versioned visual text or null when no checkpoint exists. DELETE on `/api/terminals/{id}` explicitly closes either form: the manager discards known-unused terminals immediately, while used/legacy archives start normal retention. CSRF-protected DELETE on `/api/terminals/{id}/archive` permanently removes a closed archive and its input history; live/unclosed records return 409. Preserve authentication, origin/CSRF admission and per-user worker access. Missing/foreign archives return 404; storage failures return 500 and must not trigger missing-session recovery.

# Work Guidance

Keep frontend protocol and real-system tests in sync. Do not weaken shared ownership checks to accommodate a UI caller.

# Verification

`TUXEE_SYSTEM_TEST=1 go test -race ./internal/server -run TestDisplayKeepalive` completes real VNC authentication, checks healthy idle connections and missing-pong disconnection, and verifies applications survive viewer loss. Requires `tuxee-Xvnc` and `xterm` on PATH.

Instance-cookie tests share one HTTP cookie jar across two server ports and verify exact-name admission, legacy-cookie rejection and logout/session isolation. CLI tests cover ID persistence, independent directories, private permissions and malformed/read-failure preservation. `tests/instance-sessions.mjs` checks real login/PTY/restart behavior across two Docker runtimes.

Run `go test ./internal/server` for direct/proxied origin/CSRF/logout admission (including terminal display routes), request-scoped TLS metadata and SNI/default identity, connection readiness/authentication, restart permission/admission, shutdown unavailability/session cancellation, authenticated system information and metrics, process snapshot/CSRF/selection admission, monitoring preference validation, OS-release parsing, eight-cell bounds, legacy layout migration and discarded legacy file aliases, and compressed index/CSP integrity. Real PTY transport tests cover binary/window ordering, ordered pipelined input, frame/byte limits with blocked stdin, invalid frames/acknowledgements, compressed snapshots and output draining while input blocks. `TUXEE_TERMINAL_BENCHMARK=1 go test ./internal/server -run TestTerminalThroughput -count=3 -v` measures a 256 KiB real PTY stream with zero/25 ms simulated acknowledgement delay and snapshot wire bytes; it is not a browser or WAN benchmark. Run with `-race` for lifecycle changes. `TUXEE_SYSTEM_TEST=1 go test ./tests` runs real HTTP/WebSocket takeover, reconnection and no-timeout retention checks against the built executable.

HTTPS redirect checks cover preserved URLs, invalid/oversized headers, plaintext isolation, idle clients, HTTP/2, TLS-ALPN certificate challenges and shutdown. The real-system test follows the redirect through the built binary.

Content APIs use the same authenticated user worker. File-operation JSON is bounded at 8 MiB to accommodate escaped 1 MiB editor pages, including their original byte ranges and hashes. Inline previews allow only selected image/PDF/audio/video MIME types, never HTML/SVG. The /api/preview/{filename}?path= route carries the original filename in its URL and Content-Disposition for native viewers. Responses are private/no-store, use same-origin frames with restrictive CSP, and support validated single byte ranges plus HEAD. The main CSP permits local frames/media for those previews. Test malformed/suffix/open-ended ranges and active-content exclusions.
