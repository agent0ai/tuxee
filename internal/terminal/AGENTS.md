# Purpose

Retained Linux PTYs and canonical display recovery.

# Ownership

Own session identity, process groups, bounded output, browser controller leases, and explicit termination. Shells use local PTYs without an SSH transport. Each session owns an optional lazy internal/desktop display and a reference to the manager's shared internal/audio runtime for its Linux UID. Prepare both environments before starting the shell. Close the display and release the audio reference after shell exit; explicit closure waits for that cleanup. All sessions for one UID receive the same PulseAudio endpoint, including when X11 is unavailable.

# Local Contracts

Terminal error events carry structured i18n `text` plus diagnostic `message`; include metadata in queue byte accounting. Goja error objects preserve their key/vars through synchronous throws, rejected promises and engine faults. Each browser renders Tuxee notices in its own login language; shell/GUI output is application data and is never translated by the browser.

`language.go` discovers installed locales once per server process through bounded `/usr/bin/locale -a`. Creation receives the authenticated language, sets GNU `LANGUAGE` preferences (for example `cs:en` or `pt_BR:pt:en`) and selects an installed UTF-8 `LC_MESSAGES`, preferring the exact region then the same language. Missing locales use `C.UTF-8`; never set an unavailable locale. Keep the base `LANG=C.UTF-8`, leave `LC_ALL` unset and preserve numeric/date formats. Child terminal and GUI programs inherit these defaults; user startup files may override them. Existing terminals keep their environment across reconnect/logout/new browser languages. Never install locales, write profiles or change file/process helper environments. Applications need their own translations; GNU gettext may stay English without a non-C system locale. Restart after installing new system locales to refresh discovery.

Start shells with `umask 022` in the credential-dropped child before login startup files run, for both interactive and command terminals. System/user shell profiles may override it; commands and GUI apps inherit the resulting mask. Keep the server's `077` mask and private helper/runtime files unchanged. Exec the selected shell in place to preserve the tracked PID and process-group cleanup.

`shell.go` embeds the small shell startup/prompt scripts. Shell command defaults to `bash`; interpret its executable/arguments only in the credential-dropped child, never in the server. Set SHELL to the selected executable. Terminals use interactive login startup. Initial commands run once in that same shell after startup files, retaining cwd, shell variables, exit status and the selected prompt after completion or Ctrl+C. Ordinary command failure does not end the terminal; explicit `exit`, shell-replacing `exec` and shell death still do. Never send initial commands as simulated PTY input or replay them on reconnect/adoption. Missing shells fail visibly; never install a shell or silently substitute one.

The per-user prompt preference defaults on and affects only new Bash, Zsh and Fish terminals, including initial-command launches. Write embedded scripts into a private per-session directory under `/tmp`, readable by its owner; remove it after shell exit or failed creation. Initial commands are appended to private startup scripts, interpreted only by the credential-dropped selected shell. Bash uses `--rcfile` and explicitly sources `/etc/profile` plus the first readable `.bash_profile`, `.bash_login` or `.profile`, then the app prompt. This mode is interactive rather than Bash's `login_shell` mode. Zsh temporarily redirects ZDOTDIR through startup wrappers, sources the user's files through `.zlogin` and restores ZDOTDIR before the command/prompt; Fish uses its native `--init-command`. POSIX shells use `ENV` for initial commands, restoring/sourcing the previous ENV startup file. Omit app prompt scripts when the preference is off. Other shells retain their own prompts. Startup-disabling flags or shell wrappers that ignore these native startup mechanisms may bypass integration, including initial commands. Never edit user startup files, change their login shell, add prompt dependencies or install global profiles.

`prompt.bash`, `prompt.zsh` and `prompt.fish` show a bold green `#36cfa7` home-abbreviated path, gold `#fdbc03` active virtualenv/Conda name, purple `#ad94f7` Git branch (short hash when detached), and default-foreground `❯`. Count the full inline text without color codes: below 25 characters stays inline; otherwise prepend a blank line and put `❯` on the second line. Bound Git calls to 250 ms, tolerate absent Git, sanitize control characters and render names as data, including Zsh percent escapes. Reset color before input, honor NO_COLOR/TERM=dumb, preserve existing prompt hooks and avoid duplicate environment labels. No runtimes, tags or commit counts.

Attachment loss never kills a shell. There is no idle or detached timeout. Explicit termination, process exit and unrecoverable terminal failure end it. Tuxee shutdown/re-exec detaches guardians; Linux/container shutdown ends processes. User ownership is checked before attachment and control. Persistent creation requires a usable private metadata directory for discovery and the guardian socket; refuse creation if it cannot be prepared.

`RunningCount` supplies the CLI’s private status aggregate under manager/session locks. Include attached and detached live terminals; exclude exited, closed and post-mortem sessions. Counting never attaches a viewer, reads archives or changes terminal lifetime.

With archival enabled, output EOF captures final text and releases the ended session/engine; API lookup falls back to its archive. Isolated managers without an installation ID retain ended output in memory for attachment tests. The frontend must persist a new session ID before connecting, and coalesce creation while its panel is being remounted.

Serialize process-group signals with child reaping. Never signal a retained terminal's numeric PID after it has exited and been reaped.

`WorkingDirectory` resolves the live tracked terminal process's `/proc/PID/cwd` through the credential-dropped file worker. Hold the session lock through the bounded, cancellable lookup so PID reuse cannot redirect it; reject closed or reaped sessions. The result is the process's current directory, not historical output or necessarily a nested shell's directory.

Manager.Detach checkpoints the guardian and flushes the user-owned post-mortem files before releasing Go controllers, while native guardians retain the shell, descriptors and GUI/audio streams. Serialize the durable flush with archive/history/closure; it must not depend on an archive API read or the five-second timer. Manager.Close explicitly terminates sessions and waits for every session's cleanup, including sessions already removed from the visible inventory by a concurrent Close. Force-killed shells must be reaped and their displays closed before cleanup completes, before destructive cleanup reports success. A failed guardian stop preserves terminal metadata and returns an error.

Snapshot capture is admitted before allocation: at most two unacknowledged recoveries globally and 32 queued requests. Waiting is context-cancellable; release admission on snapshot acknowledgement or transport closure, including failed capture. Serialized snapshots are limited to 64 MiB separately from each attachment's 1 MiB/512-event live queue. Queue accounting includes events already sent but not rendered. Slow views detach without terminating the PTY; input cancellation never implies that accepted bytes can be replayed.

An attachment may carry a browser-generated viewer ID scoped to its terminal. Reattaching the same viewer retires its old attachment and cancels even a half-open transport before recovery admission. Release the old snapshot permit only after its transport closes. Preserve another viewer's controller ownership; older clients without an ID remain independent.

Display/window state travels in the initial snapshot and subsequent `display` events on the existing terminal attachment. Include window metadata in attachment queue byte limits. The browser can hide either renderer without detaching or terminating the PTY.

Create initializes the canonical background and foreground before shell startup. Manager.SetBackground applies changed background/foreground preferences to every owned retained session, including detached/ended sessions, under its output lock and broadcasts an ordered `background` event. Keep the current/default background and foreground in snapshots and application query/reset replies. Unchanged preferences preserve application overrides; ANSI palette entries, parser state, shell identity and other users stay untouched. Engine update errors use existing terminal error events without undoing saved settings.

`history.go` also owns manager-level draft reads/saves for live and archived terminal IDs through the credential-dropped file worker. Serialize revision checks and writes with the archive/history/closure lock, bound requests to five seconds and never take the output lock for draft I/O.

`history.go` keeps the last 50 nonempty exact drawer submissions, consecutive deduplication and the 64 KiB entry limit. Append only to live terminals; preserve the file when a terminal dies or a used/legacy terminal is closed. Serialize appends, checkpoints and reconciliation with the manager lock; never hold the session output lock during credential-dropped filesystem I/O.

Persist `used` in archive metadata: initialize it from a nonempty creation command and latch it on the first nonempty input accepted from the controlling attachment. Rejected input, output, resizes, attachments and engine-generated terminal replies do not count. Mark the archive dirty when usage changes. Explicit closure passes known usage even if the final output checkpoint fails. Unused terminals remain recoverable until explicitly closed; the file worker discards them on closure. Legacy records with no usage flag retain normal retention.

`archive.go` checkpoints changed output every five seconds and samples fullscreen output every second. Keep one chronological transcript of shell output and the last useful fullscreen screen from every application visit, with capture time. Bound shell and application rows together to 5,000 rows / 512,000 cells, retaining the newest rows. Preserve fixed columns and emitted blank lines, without unused shell screen padding. The shared adapter attempts a final sample before fullscreen exits or terminal resets; blank clears keep the previous useful sample. Capture before deliberate terminal termination signals, since exit handlers may clear output. Record `startedAt` after successful process start and `terminatedAt` when process exit or terminal termination is observed, preserving the first observation. Natural exit, fatal terminal errors and Linux/container shutdown leave dead/unclosed metadata; only explicit closure sets `closedAt`, including when racing natural cleanup. Terminal Restart closes the old record through the same operation before creating a replacement. Capture/storage is best-effort, not auditing; log failures without preventing shell use. Runtime snapshots are not durable archive files.

The CLI supplies `HistoryInstance` and calls `StartArchives` with its state directory before serving. Initialize shared audio with the same instance before any browser can subscribe, even when no terminal exists yet. `archive_accounts.go` atomically remembers successfully authenticated username/UID pairs in `terminal-accounts.json`; startup/hourly cleanup resolves current identities and skips mismatches. Login, creation and closure also reconcile. The user-owned file worker marks stale live records dead and expires only explicitly closed archives using current settings. Never infer identity/liveness from stored PIDs or expire unclosed records. Keep each account’s terminal directories flat under its resolved XDG state directory and scope records to the installation ID. Manager shutdown stops and waits for the cleanup job. Explicit archive deletion is manager-serialized, rejects live sessions and delegates closed-record validation/removal to the user worker. Late checkpoints or repeated closure cannot recreate a deleted archive.


Persistent sessions commit a versioned engine/archive checkpoint before shell launch, then replay the guardian's ordered journal after adoption. Slot 0 contains the checkpoint; slot 5 is the shell-owned audio lifetime reference. Jobs 1/2 are the shell and optional display. Journal event kinds 4–7 represent colors, usage, archive sampling and synchronized-output flush; resize is kind 3. Checkpoint after each MiB consumed and on graceful detach. Preserve snapshot schema readers across application updates; never replace a live guardian to upgrade it. Discovery/adoption finishes before initial archive reconciliation and HTTP startup. An unavailable guardian remains protected by its directory lock.

# Verification

Run `go test ./internal/terminal -v`. Engine checks cover split Unicode, two-column emoji/cursor replies using the shared Unicode 11 provider, parser continuation, alternate screen, query replies, synchronized-output deadlines and snapshot recovery. Root-only real PTY checks cover PID retention, takeover, indefinite detachment, explicit termination and manager shutdown waiting for an already-closing HUP-resistant shell to be reaped. Snapshot tests cover serialized byte limits, global admission/waiter bounds, cancellation and release on acknowledgement/closure. Use `-race` for lifecycle changes.

`TestShellCommand` covers multiline initial commands, same-PID/cwd continuation, nonzero exit status, Ctrl+C, once-only execution and startup cleanup under Bash/Zsh/Fish/POSIX sh with prompts enabled/disabled.

`TestShellPrompt` uses real credential-dropped PTYs for Bash/Zsh/Fish, enabled/disabled prompts, startup files, selected SHELL and retained PID. `TestPromptLengthsAndLiteralNames` checks 24/25/26 characters, Unicode and literal unsafe names across installed shells; optional Zsh/Fish checks skip when unavailable. `bash tests/shell-prompt.bash` checks detailed Bash colors, metadata and hook behavior. `node tests/shell-settings.mjs` verifies settings through the real browser/API.

`TestLanguageEnvironment` covers exact-region/base-language UTF-8 selection, GNU fallback lists and unavailable locales. `TestTerminalChildLanguage` checks a real PTY child inherits message preferences without altering numeric/date categories. The i18n browser suite checks authenticated selection and retained/new terminal environments across Czech/English logins.

`TestShellUmask` covers interactive/command root shells, an unprivileged shell, child commands, login-profile overrides, file/directory modes, unchanged shell PID and the server's private mask.

`go test ./internal/terminal -run '^$' -bench BenchmarkSnapshotCapture -benchtime=3x` measures server snapshot capture time and allocations for 5,000 lines at 80 columns and 2,000 at 240 columns. Setup/output parsing is excluded; this is not a network or browser measurement.

`TestVisualArchiveTimeline`, `TestVisualArchiveNormalFullscreen`, `TestVisualArchiveReset`, `TestVisualArchiveShellRows`, `TestVisualArchivePartialLineReflow` and `TestVisualArchiveBounds` cover ordered repeated application visits, exact Unicode/spacing, intentional blank lines versus unused rows, partial-line/reflow continuation, blank-exit fallback, normal-buffer fullscreen redraws, hard terminal resets and combined bounds. `TestExplicitCloseAfterNaturalExit` verifies timestamps, closure intent and deletion racing late checkpoints/closure; `TestArchiveCleanupRegisteredIdentity` exercises the hourly cleanup path and identity mismatch. `TestKeeperRequiresMetadataDirectory` rejects undiscoverable persistent terminals while preserving unrelated files. Run these and history races with `-race`. `TestTerminalUsageRetention` covers rejected/automatic input, resize/attachment neutrality, accepted arrows/Enter, creation commands, unclosed preservation, explicit removal and failed-checkpoint retention.
