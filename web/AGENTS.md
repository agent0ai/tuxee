# Purpose

Embedded browser application and build artifacts.

# Ownership

This document owns this subtree.

# Local Contracts

Build assets locally and embed them in the Go binary. Retain the matched xterm browser/headless version and full upstream state recovery. Do not persist passwords. Model workspace layout separately from mobile presentation.

Workspace, panel and transfer IDs share model.ts's 128-bit random ID helper using getRandomValues, which is available on plain HTTP as well as HTTPS.

No frontend CDN or external runtime asset requests. Keep editable TypeScript/CSS modules separate; build a single self-contained index.html with locally bundled dependencies and precompressed gzip. Its inline script is admitted by a generated SHA-256 CSP hash, not unsafe-inline. The download service worker remains a separate local file as required by browsers.

Brand assets are local `tuxee-logo-*.webp` copies of the user-supplied originals in `../assets/`, cropped and sized for the UI. Preserve those originals. The build inlines WebPs as data URLs: horizontal logo in the desktop header, emblem in compact mode, centered vertical logo on login. Login has floating fields and a sign-in button without a form background, border or shadow. Retain the artwork's dark backdrop for legibility in light mode.

The workspace logo is a keyboard-accessible About button. It and the user menu's About item open the same modal with the full centered vertical logo, no visible heading, and a system-information table from authenticated `/api/system`: Tuxee version, operating system, kernel, architecture, hostname and signed-in account details. Retain its accessible About Tuxee name and close button. Keep loading/errors inside the modal and cancel its request on close.

Terminal colors belong to the canonical terminal state. UI theme changes and layout resizes must not reset application-defined colors. Downloads use the server's Content-Disposition, because Chromium's download attribute bypasses service-worker progress. When the download worker is unavailable, use the browser's normal download flow silently; do not show explanatory HTTPS/localhost notices.

App scrollbars share slim rounded thumbs, transparent tracks and subtle light/dark colors in style.css, including xterm's custom sliders. Terminal scrollbars retain dark-surface colors and their full drag target. Use native thin scrollbars where custom pseudo-elements are unavailable; preserve system styling in forced-colors mode.

Reconcile panels by ID without recreating neighboring views. Workspace transitions keep outgoing/incoming boards side by side until a directional slide finishes, then detach outgoing views. Pointer dragging moves the original panel, preserving its grab offset. Over another panel, the cursor selects that target and its split edge or center swap, taking priority over empty placement unless a grid target spans both vacant and occupied cells. In empty space, model.ts gridDrop selects a rectangle from the cursor: a cell center selects 1×1, an internal grid line selects 2×1 or 1×2, and a crossing selects 2×2. Use a 32px boundary band, capped at 20% of the cell dimension. Ignore the moving panel's occupied cells and original size; preview and place the same rectangle. When it overlaps neighbors, shrink each to its largest remaining rectangular footprint, keeping at least one cell in each dimension. Reject the entire drop if a neighbor cannot remain; never move unaffected panels or split/remove a neighbor. Targets spanning vacant and occupied cells work from either side of the boundary. Reject out-of-bounds drops. Show vacated cells while dragging. Keep translucent grid cells and all docking highlights above components, including the dragged panel, in an isolated grid stacking context. The dragged panel uses 80% opacity; grid hints use a faint transparent fill so window content remains visible. Restore full opacity on drop/cancellation and animate its size and position to the target. The same placement applies when dragging add icons. Outer screen-edge snapping retains priority. Valid drops animate into position; cancellation/invalid drops animate back. Never substitute browser drag images or clone terminal DOM. Explicit panel/workspace closure starts background terminal termination, including pending creation and inactive workspaces; failures do not block UI removal. Switching workspaces, browser closure and logout only detach.

Docking uses one workspace-owned highlight: slide and resize it between targets in 120 ms and fade it in/out in 80 ms, keeping target selection immediate. Empty-space, screen-edge and split/swap highlights share the same layer above panels. Retargeting cancels pending removal; the first appearance starts at its target bounds. File-drop highlights stay component-bound and only fade in/out in 80 ms; file-drag.ts retains their label through fade-out. Respect reduced motion for all highlights.

Use one terminal header with rename/close, no status/header duplication or modifier button row. The username and menu icon form one anchored menu button. Desktop workspace rename/close buttons live inside their tabs, including overflow entries; compact tabs use their context menus. Keep labels and errors concise, with no descriptive/promotional microcopy. Terminal surfaces retain their canonical palette in both UI themes.

file-drag.ts owns internal pointer gestures, typed file selections, target registration and shell quoting shared by file browsers and terminals. Native browser/OS drag negotiation must not decide internal copy/move: macOS filters Control/Command operations before JavaScript receives a drop. External uploads use native DataTransfer directory entries/files; capture them synchronously inside drop/paste events. Entire panels accept file drops; copy/move progress is non-modal and successful arrivals animate. File-to-terminal drops insert quoted paths without executing a command.

# Work Guidance

# Verification

Run `npm run build` for generated assets, `npm run test:layout` for bounded layout rules, `npm run test:dividers` for focused shared-gap and overlapping-drop checks, and `npm run test:browser` / `npm run test:tabs` sequentially against the real binary. Terminal interpreter checks live in `internal/terminal`. Rebuild the binary after frontend changes.
`dist/` and `../internal/terminal/engine.js` are generated and ignored by Git;
build them before Go commands on a fresh checkout. Vendored source stays in Git.

## Interaction contracts

- New standard landscape desktop workspaces start two file browsers stacked in the left half (`/` above the signed-in user's home) and one full-height terminal in the right half. Ultrawide defaults retain two file browsers followed by two terminals; portrait/mobile defaults retain one file browser and one terminal. The first file browser starts at `/` and the second, when present, at the signed-in user's home (`/root` for root). Default terminals start at the user's home. Apply defaults only on creation; preserve saved paths. The file toolbar's Open terminal here creates and activates a terminal in the browser's current directory through the shared panel-add flow, with full-workspace errors local to that browser. Toolbar controls wrap in narrow panels.
- monitor.ts owns live resource summaries, details and configuration. Desktop shows compact gauges after the add/layout controls, before the theme switch, separated by pipes; hiding the widget also hides its separator. On desktop and mobile, the account menu contains only a plain Resource monitor action opening the Resource monitor modal; never render gauges in the menu or a Host/Container badge in the modal. The modal's Display resource monitor widget switch saves `monitoring.hidden` per user, defaulting to shown when absent. Hiding gauges preserves selected metrics and stops polling while the modal is closed, including while the account menu is open. Closing a quick-look modal stops polling again while display is disabled. Every account menu retains a Resource monitor entry; opening it fetches live readings even when display is disabled, and the switch can re-enable gauges. Defaults are CPU, RAM and `/`; the detail cog selects CPU/RAM/swap, disks, network interfaces and 2/5/10-second refresh. Persist through user settings. Show up to four summary metrics (three on narrow desktops) and a +N count for the rest; details show every selection. CPU readings from 0.1% to below 10% retain one decimal; readings below 0.1% show 0%. Preserve access even when nothing is selected. Poll once per interval without overlap, pause in hidden documents, abort on logout/disposal, and report unavailable data rather than stale healthy readings.
- Monitor readings keep constant widths. CPU uses a five-character percentage field; RAM/swap/disks show used bytes, with percentage rings and full used/total details. monitor-values.ts formats sizes and network bytes/second into four-character, space-padded decimal B/K/M/G/T/P/E fields: one decimal below 10, whole numbers otherwise, promoting units before rounding would overflow. Network readings have independently colored download/upload values. Their ring fills from noon counterclockwise for download and clockwise for upload, each capped at six o'clock. Scale each direction independently against twice its mean over the latest 100 distinct received samples, including zero and the current sample; a steady positive rate fills half its semicircle. Cached timestamps and repaints never add samples. Unavailable rates reset that direction's baseline; disappeared interfaces discard history. Keep history only for the current monitoring session.
- Compact mode depends only on viewport dimensions, never the selected workspace or its saved grid. Mobile content has no panel frame/title bar; controls and names live in component tabs. Theme/account controls stay right-aligned. On desktop and mobile, the account menu shows a user icon before the username.
- overflow.ts adapts the8020/uui header fitting to move excess workspace/component tabs into a three-dot popover. Keep the active tab visible when it fits. Overflow icons/names align left. Mobile workspace/component tabs have no inline close/rename controls. Dispose observers and menu listeners with chrome.
- Context menus use ui.ts popovers at the click or invoking control, with Up/Down navigation and Escape restoring focus without clearing selection. Confirmation dialogs initially focus the confirming action.
- New workspace creates and activates `Workspace N` immediately using the existing count-based default, without a naming dialog. Preserve the workspace limit and unsaved-edit confirmation. Users rename later through the desktop tab's pencil button or the tab context menu; the account menu has no Rename workspace action.
- Workspace and component tabs offer Activate, Rename and Close on right-click or ContextMenu/Shift+F10, including overflow tabs. On mobile, a 500 ms long press opens the same menu; movement, scrolling, cancellation and header disposal cancel pending holds. Consume the release click, including when an overflow tab leaves the DOM, so a hold never activates a tab or action. Disable Activate for the current tab. Reuse confirmed workspace closure and terminal termination; return focus to the appropriate overflow button on dismissal. Component menus also expose Take control when a terminal needs it.
- Both file browsers and terminals have desktop rename icons and mobile menu actions. File-browser labels use optional per-user `Panel.name`; preserve overrides across navigation/reload without changing filesystem names. Reset removes the override and resumes the current-folder title (Files at `/`). Terminal names remain session-owned; Reset renames the session to Terminal. Rename dialogs offer Reset, Cancel and Continue.
- File rows preserve focus across navigation/refresh only while focus still belongs to the original control or that list; delayed responses must not steal focus from another component or editing field. Up/Down moves focus, Right enters directories, Left returns to the parent, Space toggles selection, and Alt/ContextMenu/Shift+F10 opens the menu. The action and dialog are named Properties. Properties accept multiple selected entries and show summed entry sizes/common values; directory sizes are inode metadata, not a recursive scan. Permission changes apply to each selected item under the user's credentials and can partially succeed.
- File browsers have no command row or embedded terminal. Content extends to the bottom; corner grips overlay it. File copy to the same path delegates sibling-name allocation to the filesystem worker and uses the returned destination for arrival animation.
- File-list folder icons are filled with the accent color; regular-file icons remain outlines.
- Download sends one regular file directly; any folder or multi-item selection streams one ZIP while compressing. Show an indeterminate progress bar, growing compressed ZIP size and Cancel in the originating browser. Poll session-bound server progress so ZIP progress/cancellation also works over plain HTTP without a service worker. Cancel removes the server job and stops compression/transfer; completed jobs are released. Never require users to open folders first or publish temporary ZIPs in their directories.
- Component-related notifications and progress live within that component; global actions use viewport notifications. ui.ts owns notification routing, including controls moved into menus/mobile tabs.

- Internal file dragging carries a source-panel ID and typed selection in one pointer session. Control, Command or Option select Copy at release; otherwise Move. File-browser drop targets always say Move here without a copy modifier and Copy here with one, including the source browser; show the copy modifier hint only for Move here. Update feedback on pointer/key changes, cancel on Escape/pointer cancellation/blur/disposal, and suppress the post-drag click; dragging within the originating browser never moves files. Skip identical-path moves before starting progress. The drag image/drop animation summarizes the complete selection, including folder/file counts. Keep Copy/Move labels and modifier hints on file-browser drop targets only, never in the dragged group or terminal target.
- Type-to-filter reveals and focuses an editable footer search field. A footer filter button opens/focuses it on touch devices and toggles it off; Escape clears/closes it, and Enter/Up/Down returns to the list. Filtering is local to the loaded directory. Column buttons cycle ascending, descending, default with an active triangle indicator; explicit sorts compare column values across all entries and persist across directory navigation in that browser. Default order is folders first, then names. Shift+Up/Down extends/shrinks a contiguous selection anchored at the first row; context-menu Escape never clears selection or the filter.
- Single-click selection and double-click opening work across the entire file row, including blank name-column space, stats and row padding. File dragging starts only on names/icons, whose hit areas fit the filename width and fill the row height without vertical gaps. Dragging from blank space after a filename, list margins or stats starts rectangle selection. Capture row-origin selection gestures on that row so clicks retain their row target; suppress the click after a rectangle drag. Pointer press preserves selection; clicks change it on release, while drags change it only after crossing the movement threshold. Background clicks clear selection; rectangles select intersecting full row bounds, including stats and blank row space, with vertical edge auto-scroll. Keep the fill at 12% opacity so selected text remains readable. Control/Command/Shift adds to existing selection; Escape/cancellation restores it. Clean up capture, animation frames and listeners on completion, navigation, refresh or disposal. Touch keeps native list scrolling.
- transfers.ts owns the upload batch shared by file input, OS drops and clipboard files. Enumerate directories recursively, including empty folders and every readEntries batch, then stream one file at a time. Snapshot the destination once. Show one local indicator with completed/total file count and aggregate bytes; cancel stops the active request and remaining queue, retaining completed items. Component disposal/logout also cancels. Use worker-returned paths after collision naming; a renamed folder remains the parent of all its children.
- file-drag.ts owns native drop/paste admission alongside internal pointer dragging. Prevent default file navigation across the document, ignore outside drops, and accept uploads over the entire available panel. Terminal uploads require a connected controlling view, create the user's ~/uploads as needed, and paste quoted top-level result paths only after complete success and a fresh control/liveness check. Focus the terminal on upload initiation, never steal focus on asynchronous completion. Never press Enter. File browsers upload to their current folder. Native paste consumes only exposed files; generic screenshot images use clipboard-image.png and numbered collision variants. Preserve plain text paste and editing fields; intercept xterm file paste before its text handler. Do not read the clipboard in the background or infer local paths from clipboard text.
- Terminal drop feedback reuses the file browser's filled, dashed-border `data-drop` overlay above xterm. External file drags say `Upload and paste`; internal file-browser drags say `Paste`. Keep it non-interactive and clear it on leave, rejection, drop or disposal.
- New file and New folder are toolbar and directory-background menu actions, excluded from item context menus. New file reuses the zero-byte upload path and its credential-dropped, no-overwrite collision contract.
- Directory-background menus also offer Properties for the current folder. The shared Properties action uses selected entries when present, otherwise the browser's current path, including `/` and empty folders; the footer info button follows the same rule. Reuse the existing user-scoped stat/chmod operations.
- Screen-edge zones show half/quarter targets and model.ts reflows other panels within grid bounds. Rearrange compares bounded rectangular splits using actual pixel dimensions, favoring wider terminals and compact file lists. Group files left/terminals right, or files above/terminals below in portrait; allow stepped boundaries to recover usable space. Balanced targets more area per terminal, retains reading room for both types when possible, caps widths at 640px for files and 1440px for terminals at grid-cell resolution, and centers spare side space. Priority modes initially pack the other type into single cells and maximize the chosen type's area before scoring grouping and shape; lift the pixel width cap for the chosen type, but keep file browsers at most two cells wide in every automatic mode. After calculating any automatic layout, expand each panel into the largest free rectangle containing its footprint, processing the priority type first. Preserve the same width limits (640px files/1440px terminals for non-priority panels), never shrink a panel or move/cover neighbors, and leave cells unused only when bounds or width limits prevent expansion. Apply that cap while arranging, not as a post-layout resize; center spare space around the group. Manual/custom layouts remain unrestricted. Prefer full-height file lists and readable terminal shapes within those constraints.
- Rearrange cycles Custom → Balanced → Terminals → Files → Custom. Persist `workspace.layout` with mode 1/2/3 and the original per-ID geometry only; restoring must preserve current paths and terminal IDs. Automatic modes may coincide when the available space and width limits produce the same useful layout; never minimize panels merely to make modes look different. Use a locally bundled asymmetric layout icon, rotating clockwise by 90° per click; upright means custom. Manual moves, resizes, expansions, additions and removals that change panel membership or any final cell rectangle clear the cycle and reset the icon upright with the Custom label. Compare per-ID geometry in the shared layout-change path; accepted drops/resizes that return to identical cells and blocked expansions preserve the mode. Cancelled drags, renaming, navigation and viewport/workspace changes preserve it. Hide the control in compact mode.
- Clicking Rearrange smoothly expands its current-mode label: Balanced, Terminals, Files or Custom. Keep it open while hovered; collapse two seconds after pointer leave, cancelling the timer on re-entry. Keyboard/touch activation without hover also collapses after two seconds. No native tooltip; retain the accessible action name and current/next-mode description. Respect reduced motion and dispose timers with the header.
- Double-clicking a desktop title expands to the largest empty rectangle containing it without moving or covering neighbors. If it cannot expand, shrink to one cell at its current origin. Persist the resulting grid.
- Shared gaps resize every panel connected along that boundary, including three/four-panel junctions. Keep integer grid snapping and one-cell width/height minimums; clamp junction axes independently. Locked boundaries have no drag handle. Preview continuous size changes on the original mounted views, then animate width/height into snapped cells on release. Escape, pointer cancellation, blur and viewport changes restore the original geometry. Support arrow keys on focused dividers, persist changed geometry, and hide handles in compact mode and during individual panel dragging/resizing.
- Pointer resizing clears divider focus on release/cancellation so the highlight does not stick; keyboard resizing retains focus.
- Capture every live resize rectangle through GridStack’s drag-driver resize callback, before helper cleanup. Animate actual width/height from the released size to the snapped size; do not scale panel text or capture an already-clamped rectangle.
- Workspace plus follows the last visible tab/overflow control. Desktop add-file/add-terminal/rearrange controls are grouped before the theme switch. In compact mode, put add-file/add-terminal after the component tabs/overflow in `.component-controls`, leaving the top bar for workspaces and account/theme controls. Keep additions outside the fitted `.component-tabs` host so they remain visible when tabs overflow; remove the whole strip on header replacement. Desktop titles and mobile component tabs include their file/terminal icon; label changes preserve it. Separate adjacent visible mobile tabs with a faint vertical pipe; overflow remains a three-dot menu. Retained-terminal management lists detached sessions only and omits session IDs.
- editor.ts integrates vendored CodeMirror 6 and UUI syntax modes; editor-page.ts owns page limits, exact line-ending serialization and visual wrapping. Unknown extensionless dotfiles default to shell; recognized extensions retain their modes and other unknown files use text. Reject binary/non-UTF-8 content before mounting an editor. Read sequential pages capped at 1 MiB and 10,000 displayed rows, counting a visual break every 1,000 Unicode code points; never insert wrapping newlines into saved content. Keep only the active page and prior byte offsets/line numbers. Text headers offer Undo/Redo and Page up/down; previous/next file controls and Left/Right navigation belong only to media previews. Page navigation requires saving pending edits with confirmation; cancellation/failure keeps the draft open. Freeze editing during reads/saves. Send the exact original byte range/hash and whole-file version on every save, use the returned range/version after resizing edits, and invalidate later offsets. Preserve untouched mixed line endings. Unsaved edits require discard confirmation on file/component/workspace closure or logout; browser navigation uses beforeunload. Image/PDF/media previews stay in the component. PDFs use the installed browser viewer; media uses HTML audio/video and authenticated byte-range streaming.
- The shared editor highlight theme must style Markdown tags: headings, list/formatting markers, inline/fenced code, links, quotes, strong/emphasis and strikethrough. Keep styles visible in both UI themes; syntax switching must not alter file content.
- Image Previous/Next buttons and Left/Right keys share circular navigation through images only, in the file browser's current visible order; skip text/PDF/audio/video and disable both for a single image. image-viewer.ts owns fit-on-open/resize, zoom out/in, percentage/100% and Fit controls, double-click fit/zoom, and +/-/0/1 shortcuts. Use a native two-axis scroll viewport for diagonal touchpad movement, momentum and touch panning; contain overscroll within the viewer. Mouse/pen dragging pans with pointer capture. Ctrl-wheel and Safari gesture pinch zoom around the pointer, capped at 1600%; ordinary wheel scrolling never changes zoom. Dispose capture, gesture listeners, image requests and resize observers when changing files or closing.
- Archive dialogs expose installed tool capabilities and optional passwords. Password fields are cleared after submission and never persisted. Progress/errors stay local to the originating component.
