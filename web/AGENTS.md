# Local Contracts

Build assets locally and embed them in the Go binary. Retain the matched xterm browser/headless version and full upstream state recovery. Do not persist passwords. Model workspace layout separately from mobile presentation.

Workspace, panel and transfer IDs share model.ts's 128-bit random ID helper using getRandomValues, which is available on plain HTTP as well as HTTPS.

No frontend CDN or external runtime asset requests. Keep editable TypeScript/CSS modules separate; build a single self-contained index.html with locally bundled dependencies and precompressed gzip. Its inline script is admitted by a generated SHA-256 CSP hash, not unsafe-inline. The download service worker remains a separate local file as required by browsers.

Brand assets are local `tuxee-logo-*.webp` copies of the artwork in `../assets/`, cropped and sized for the UI. Preserve the originals. The build inlines WebPs as data URLs: horizontal logo in the desktop header, emblem in compact mode, vertical logo in About and on login. Light-theme headers/About use `*-light.webp` variants with transparent backgrounds and black “Tux” lettering; retain the yellow hexagon/“ee” and opaque black-and-white penguin. About's light logo has no CSS backdrop. Login always stays dark with the original vertical logo, floating fields and a sign-in button without a form background, border or shadow.

Login inputs stay at least 16px to avoid iOS focus zoom; do not disable user zoom in viewport metadata. Touch login does not autofocus. Logo, gaps and padding follow the available viewport height so the form fits above the keyboard, with scrolling for smaller heights. The shared viewport height factors out intentional pinch scale; successful login blurs the form before mounting the workspace.

The workspace logo is a keyboard-accessible About button. It and the user menu's About item open the same modal with the full centered vertical logo, the project's exact tagline as a centered subtitle below it, no visible heading, and a system-information table from authenticated `/api/system`: Tuxee version, operating system, kernel, architecture, hostname and signed-in account details. Include a GitHub table link to `https://github.com/agent0ai/tuxee`. Retain its accessible About Tuxee name and close button. Keep loading/errors inside the modal and cancel its request on close.

connection.ts owns one page-lifetime backend watcher, including the login screen. Check uncached `/health` without overlapping requests (four-second timeout, five seconds between healthy checks, two seconds while reconnecting); valid API 5xx errors and unexpected terminal socket closure request an immediate check. Browser offline, API transport failures and invalid/non-JSON API responses show the overlay immediately; ignore cancelled API requests. At startup, after outages and on API 401, confirm both health and `/api/me` before dismissing recovery or showing login. Only a valid JSON 401 from `/api/me` confirms session expiry; proxy errors and shutdown responses preserve mounted views and drafts. The shared API helper reports transport/protocol failures as connection errors, never raw JSON parse errors, and ignores stale-token 401 notifications. Pause scheduled checks in hidden documents and resume on visibility/focus/online. Show a non-dismissible modal above existing dialogs with a themed blur backdrop, accessible "Connection lost, reconnecting..." status and CSS spinner respecting reduced motion. Recovery removes it without remounting authenticated views or replaying mutations/credentials. Preserve existing terminal retry/snapshot behavior; dispose the watcher/overlay only on pagehide.

Terminal colors belong to the canonical terminal state. UI theme changes and layout resizes must not reset application-defined colors. Downloads use the server's Content-Disposition, because Chromium's download attribute bypasses service-worker progress. When the download worker is unavailable, use the browser's normal download flow silently; do not show explanatory HTTPS/localhost notices.

Terminals use the system monospace stack at 13px with lineHeight 1, keeping block-art and box-drawing rows continuous. Install state.ts's view and subpixel DOM font adaptations after opening xterm so spaces, bold text and application scrollbars remain on the same column grid. Put inset padding on the full-height xterm element, where FitAddon subtracts it, rather than on its host. Paint the whole xterm surface with the canonical background, including spare pixels below the last complete row; its legacy `.xterm-viewport` must inherit that background rather than paint black over it. Preserve cell metrics and overlay corner grips without reserving a bottom gutter.

App scrollbars share slim rounded thumbs, transparent tracks and subtle light/dark colors in style.css, including xterm's custom sliders. Terminal scrollbars retain dark-surface colors and their full drag target. Use native thin scrollbars where custom pseudo-elements are unavailable; preserve system styling in forced-colors mode.

Reconcile panels by ID without recreating neighboring views. Workspace transitions keep outgoing/incoming boards side by side until a directional slide finishes, then remove the outgoing board from the visible document while retaining its cached views and connections. Pointer dragging moves the original panel, preserving its grab offset. Over another panel, the cursor selects that target and its split edge or center swap, taking priority over empty placement unless a grid target spans both vacant and occupied cells. In empty space, model.ts gridDrop selects a rectangle from the cursor: a cell center selects 1×1, an internal grid line selects 2×1 or 1×2, and a crossing selects 2×2. Use a 32px boundary band, capped at 20% of the cell dimension. Ignore the moving panel's occupied cells and original size; preview and place the same rectangle. When it overlaps neighbors, shrink each to its largest remaining rectangular footprint, keeping at least one cell in each dimension. Reject the entire drop if a neighbor cannot remain; never move unaffected panels or split/remove a neighbor. Targets spanning vacant and occupied cells work from either side of the boundary. Reject out-of-bounds drops. Show vacated cells while dragging. Keep translucent grid cells and all docking highlights above components, including the dragged panel, in an isolated grid stacking context. The dragged panel uses 80% opacity; grid hints use a faint transparent fill so window content remains visible. Restore full opacity on drop/cancellation and animate its size and position to the target. The same placement applies when dragging add icons. Outer screen-edge snapping retains priority. Valid drops animate into position; cancellation/invalid drops animate back. Never substitute browser drag images or clone terminal DOM. Explicit panel/workspace closure starts background terminal termination, including pending creation and inactive workspaces; failures do not block UI removal. Switching cached workspaces preserves attachments; eviction, browser closure and logout detach without killing shells.

app.ts owns a FIFO cache of at most eight visited workspaces, including the active one. Reuse the complete board, GridStack and component views on return; reset inert/slide state, reconcile viewport layout, and refresh terminal size/display without reconnecting. Cache insertion order is first visit, not last use. Before mounting a ninth, dispose the oldest cached workspace; retain its saved layout and running shells for normal snapshot restoration on return. Inactive boards stay out of the document so their controls cannot receive input or affect visible layout. Unsaved drafts survive warm switches; eviction and closing an inactive workspace require its canClose confirmation, and logout checks every cached workspace. Closing a workspace disposes its cached views after terminal termination is requested, including pending creation. Logout, session expiry and pagehide dispose the whole cache. Warm hidden terminals remain attached; eviction and disconnection never start an expiry timer.

Docking uses one workspace-owned highlight: slide and resize it between targets in 120 ms and fade it in/out in 80 ms, keeping target selection immediate. Empty-space, screen-edge and split/swap highlights share the same layer above panels. Retargeting cancels pending removal; the first appearance starts at its target bounds. File-drop highlights stay component-bound and only fade in/out in 80 ms; file-drag.ts retains their label through fade-out. Respect reduced motion for all highlights.

Use one terminal header with rename/close, no status/header duplication or modifier button row. The username and menu icon form one anchored menu button. Desktop workspace tabs have one chevron opening their existing Activate/Rename/Close menu, including overflow entries; compact tabs use their context menus. Desktop labels support pointer reordering with adjacent tabs sliding into place and Alt+Left/Right keyboard reordering. Persist workspace order without activating tabs, remounting views or changing the warm-cache FIFO. Escape, pointer cancellation, blur, resize and disposal cancel a drag; respect reduced motion. Overflow entries reorder vertically within their list. Component tabs retain their existing behavior. Keep labels and errors concise, with no descriptive/promotional microcopy outside the About tagline. Terminal surfaces retain their canonical palette in both UI themes.

Terminal touch scrolling belongs to terminal/interaction.ts. Text selection and copying use the terminal’s native selection; do not add a separate output-selection action, snapshot dialog or text-extraction helper.

When a saved terminal is missing (404 on initial load or reconnect) or the backend explicitly closes its session, hide its renderer and show a uniform theme-colored recovery surface. Center “Terminal session lost” with the standard primary Restart terminal button below it, on desktop and mobile. Restart creates/persists a new session and restores the terminal surface. Normal process exit retains its output; connection failures continue reconnecting instead of displaying this missing-session view.

file-drag.ts owns internal pointer gestures, typed file selections, target registration and shell quoting shared by file browsers and terminals. Native browser/OS drag negotiation must not decide internal copy/move: macOS filters Control/Command operations before JavaScript receives a drop. External uploads use native DataTransfer directory entries/files; capture them synchronously inside drop/paste events. Entire panels accept file drops; copy/move progress is non-modal and successful arrivals animate. File-to-terminal drops insert quoted paths without executing a command.

updates.ts reads cached `/api/update` once per minute while visible and on focus/visibility return; it never requests external assets or installs code. About places the update row immediately below Tuxee version. Keep status, local `DD.MM.YYYY HH:mm` check time and the refresh-icon Check now button on one line on desktop, wrapping within that row on small screens. Check now uses POST. Available releases highlight that row with a tinted background, accent edge and the existing notification icon; keep it visible when the modal opens, alongside the exact selectable command and restart warning. Keep the row available while system information loads or fails. Display check failures without losing the last check time or known update. Available releases also add the existing alert icon to About and the hamburger. Preserve known warnings on request failures. Abort polling on logout/pagehide and manual modal requests on close.
