# Purpose

Real-system integration and browser verification.

# Ownership

Own test fixtures, isolation, prerequisites and suite selection. Product behavior belongs to the owning [frontend](../web/AGENTS.md) and [backend](../internal/AGENTS.md) contracts. Keep individual assertions in the executable suites rather than duplicating them here.

# Local Contracts

- Test the real server, PAM, PTYs and filesystem. Use dedicated marked accounts, temporary fixtures and isolated listener ports. Fault injection may delay or interrupt real traffic; production contains no test hooks.
- Run browser suites sequentially, never alongside identity/account setup. Shared defaults are `tuxee-poc-a` and `tuxee-poc-b`; `TUXEE_TEST_USER` and, where supported, `TUXEE_TEST_OTHER_USER` select isolated accounts marked `Tuxee prototype test`. System suites use `tuxee-poc-system`. Refuse unrelated accounts with those names.
- Never log passwords or retain credential screenshots/traces. Capture login before filling credentials. Save screenshots and measurements only in ignored `test-results/` or `.test-state/` paths.
- Preserve unrelated settings, files, accounts, processes and containers. Restore saved settings and remove only suite-owned fixtures. Before replacing settings through the API, await pending writes and navigate away so application autosave cannot overwrite the fixture. Scope request tracking to the current document; navigation can omit cancelled-request completion events.
- Server shutdown detaches guardians. Explicitly close fixture terminals, or kill only the disposable account's processes, before deleting its account/home. Closure is asynchronous: await the DELETE response before checking process removal, including pending creation.
- Terminal creation fixtures supply dimensions and require HTTP 201 before using IDs. Untouched closure removes the terminal (404); used/legacy terminals retain archives. Supply real accepted input or a creation command when a fixture needs a closed archive. Do not blindly toggle an input drawer restored open from saved state.
- Restart/setup/update checks use disposable executables, paths and accounts. UID 0 aliases have their own home/password; never change the host root account or its settings. Force account deletion only for that alias and never delete shared homes. Fixture downloads must not install a public release over the development preview.
- Container lifecycle suites may stop, kill or replace only their explicitly supplied disposable runtime. Never use a shared preview. Follow inherited workspace instructions for Docker transport; do not hardcode a workspace socket into portable test commands.
- Real systemd checks require systemd as PID 1; Docker checks require a Docker runtime. Report missing prerequisites and skipped paths. Emulated viewport, DPR, touch, modifiers or Safari events do not establish physical iOS/macOS/Safari behavior; synthetic trees and network delays do not establish real pressure or WAN behavior.

# Work Guidance

- Keep checks small and complete; retain security, lifecycle and accessibility regressions when updating a suite. Resolve expected behavior from its owning contract, including the separate [login contract](../web/login/AGENTS.md).
- Pure UI fixtures install the real catalog explicitly; never add a bundled production fallback for tests. Copy GUI fixtures into the test user's traversable directory instead of requiring access to a private checkout.
- Use lowercase Playwright letter keys for unshifted noVNC shortcuts (`Control+a`); uppercase letters synthesize X11 Shift.
- Use `app-page.mjs` to dismiss onboarding through its real close control before application input; the How to suite uses ordinary Playwright pages.
- Wait for the relevant save/listing/animation completion before checking persistence or geometry. Deliberately delay real requests only to inspect intermediate states, then release them. Record performance without brittle machine-speed thresholds unless a suite defines an explicit latency budget.
- Source fixtures contain exact cases, pixel expectations and output filenames. This document lists how to run them and what boundary they protect; it does not certify a passing run.

# Verification

Build the frontend, native guardian and executable using the root instructions before browser/system checks. Backend package tests remain with their owners. Most isolated browser fixtures default to `bin/tuxee`; use `TUXEE_TEST_BINARY` only where the suite supports it. Suites targeting an existing server use `TUXEE_TEST_URL` and a marked account; the broad browser suite defaults to `https://127.0.0.1:9443`.

Cover dynamic shared selects as well as the independent login helper.
- `npm run check:i18n` and `npm run test:i18n`: catalog/source checks, English/Czech session flows, every built-in language, RTL, terminal language inheritance and responsive controls. Review the advisory expansion report under the [i18n contract](../internal/i18n/AGENTS.md). Supply test-only fonts for CJK, Devanagari, Thai, Arabic and Hebrew; never ship them with the app.
- `npm run test:howto`: isolated server and two accounts; first-visit persistence, navigation, responsive catalogs, current shortcuts and deferred hashed assets. Await the seen-flag save before disk/API assertions. Page-specific image fixtures and budgets live in the suite and frontend contract.
- `npm run test:shortcuts`: isolated server/account; recording, conflict validation, saved bindings, actual action dispatch and PTY/GUI/modal input isolation across platforms and languages. Go settings tests cover schema validation and migration.
- `node tests/connection.mjs`: authenticated readiness, outages, malformed/stale probes and editor preservation through reconnect/session loss. Anonymous behavior follows `login-security.mjs` and the standalone login contract: no idle readiness watcher or application overlay, and login/logout cross a document boundary. Do not restore old in-page-login expectations.
- `node tests/session-recovery.mjs`: two isolated accounts; same-account token refresh preserves drafts and PTYs, different-account login replaces the old document without replaying its edits, and archive/save retries reuse the same replacement shell.
- `node tests/workspaces.mjs`: marked account; migration, warm-cache FIFO, original DOM/socket/PID retention, drafts through eviction/logout and inactive closure. Restore settings and remove fixture sessions/files.
- `node tests/default-directory.mjs`: isolated server/account; inherited defaults, actual shell cwd, Home/path actions and desktop cloning with fresh terminals and independent drafts. Model/settings tests cover names, Unicode byte limits and geometry identity.

Pair lifecycle changes with workspace/component/divider, retained/reset/connection/lost/restart suites.
- `node tests/terminal-draft.mjs`: isolated server and two accounts; persistent Unicode drafts, revision conflicts, save/navigation guards, history/undo, reset/archive migration, account isolation and server restart. Close terminals before deleting accounts.
- `node tests/terminal-history.mjs`: `TUXEE_TEST_CONTAINER` and `TUXEE_TEST_URL` must identify a disposable Docker runtime. Run through `dbus-run-session`; the suite deliberately kills/restarts it.
